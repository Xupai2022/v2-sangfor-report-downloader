## 工作簿结构

主输出是一份 Excel 工作簿，**当前 7 个 sheet**（顺序即 `data.xlsx` 模板顺序，代码不重排）：

```text
数据统计 / 暴露面 / 资产漏洞表 / 资产表 / 告警表 / 事件表 / 弱密码表
```

- `数据统计` 是**人工填写区**，样式层一格都不碰；它同时也是 PPT 的取值来源。
- 第 7 个 sheet `弱密码表`（`MIGRATION.md` R3a）：弱密码总表**已接**（2026-10-08，平台导出
  原样落表 29 列）。但「数据统计」里读它的**格子口径**仍待投喂 —— sheet 有数据、单元格可能还是空的。
- 覆盖到的 sheet 暂为 6 个：`暴露面` 仍留模板空表（暴露面总表尚未接）。
- 文件名：`{客户或customer_id}_report.xlsx`。

数据来源是本仓库自定的六份总表口径，不是老版本的行为。

## 表格预处理（独立阶段）

**2026-10-12 起只跑一处**（用户口径：**取值层必须在预处理之后**）：

- **下载之后、解析之前**（`mssw_preprocess.js` → `report_preprocess.py` 的
  `preprocess_event_file`）：**原地改写事件表下载件**（sheet 名改回原名，内容只多那几列）。
  日志以 `===== 表格预处理（下载之后、解析之前）=====` 标示。
  这样取值层（G7）读到的就是处理过的表；搬表本来就读磁盘 xlsx，报告 sheet 自动带上那几列。

⚠️ 第 2、4 步**不是幂等的**（在最后一列右边盲追加），所以**只能跑一处**：跑两遍会追加出
重名表头，解析层会当成「平台改了列名」直接抛错。`report_writer.buildReport` 收的
`options.preprocess` 只是那次跑的**汇总**（并进返回值讲日志），不会重跑。

三件事的顺序不能换：

1. 读 `资产表` 的「IP地址」「互联网暴露」两列，建 IP → 内网/外网 映射。
   口径：`暴露` → **外网**、`未暴露` → **内网**、`未知` → **未知**
   （三种之外的取值一律按 `未知` 处理，并在日志里报出原始值，不静默）。
2. 对 `事件表` 每行取「影响资产」的 IP 查上面的映射，在**行尾追加**一列 `内网外网资产`。
   查不到填 `不在资产表`；「影响资产」为空的行留空。原有列一个都不动。
4. 对 `事件表` 精确取五个时间列，两两做减法，在**第 2 步那列右边**再追加四列
   （用户 2026-10-10 口径，值都是**分钟数、保留 2 位小数**；「响应时长」是当天追加的第四条）：

   ```text
   遏制时长 = 事件遏制时间 - 专家研判时间      （落在「内网外网资产」右边第 1 列）
   识别时长 = 事件创建时间 - 组件检出时间      （第 2 列）
   处置时长 = 事件闭环时间 - 事件创建时间      （第 3 列）
   响应时长 = 专家研判时间 - 组件检出时间      （第 4 列）
   ```

   某一对里有一个时间格是空 / 横杠占位符（`-`、`－`、`—`、`–`）就**跳过那一格**、
   留空 —— 留空是有意的：`0` 与「算不出来」在报告上必须是两回事。跳过**按行、按列独立**
   （同一行的另外几对照算）。解析不出来的值（平台换了时间格式）同样留空，但走另一条计数
   并在日志里报样例。**算出来是负数的同样留空**（用户口径 2026-10-12）：时长不可能为负，
   负差值说明至少有一个源列不是要算的那个时间（取错列 / 两列对调 / 回填了脏数据），
   写个负数进交付物等于把「这行没数据」说成「提前完成」——它走**第三条**计数，
   与「空值」「解析失败」分得开（整列一半是负数 = 多半取错了列，这个信号要能看见）。
   `0` 本身是合法值（两个时间落在同一分钟），只有**小于 0** 才判不合法。
   三种格子形态都认：文本、真 datetime、裸序列号 + 日期格式（构建那一刻表里就是第三种，
   见 `build_report.py` 的 `to_serial_number`）。

表头按**内容**找、不认行号。**有表头但缺列**（平台改了列名）会**直接报错**，不会产出一份
悄悄少一列的交付物；**表是空的**属合法状态，记日志不报错（映射为空时额外告警一句）。

> **编号保留 1 / 2 / 4 不重排**（多个文件按这几个编号指代这几步）。曾经的第 3 步是
> 「告警表『主机IP』剥掉行尾的括号说明（`172.101.226.10(未归类组)` → `172.101.226.10`，
> 全半角括号都认，2026-10-09 口径）」，**2026-10-12 用户决定删除**：
> 那一步跑在合并报告时，只改交付物里的表、**不参与任何取值** —— 取值层读的是下载件，
> 靠 `stats/metrics/rows.js` 的 `normalizeIp` 自己剥（它同时是 `report_preprocess.py`
> 的 `normalize_ip` 的镜像）。于是「主机IP」在仓库里有两个形态：报告 sheet 剥干净、
> `ctx.alarmRows` 带括号。删掉它，两个形态合一，**且零代价** ——
> 交付物里从此保留平台原样。
>
> 当初那条「没有哪一格消费这一列」的说法是**错的**：G6/H6/I6（核心系统威胁告警数量）
> 就在用「主机IP」（见 `stats/metrics/alarm.js` 的 `HOST_IP_COLUMN`）。它们不受影响 ——
> 比对的每一步都先过 `normalizeIp`，剥不剥命中同样多的行。
> `scripts/verify_write_layer.py` 的【3.6】现在反过来钉住「报告 sheet 上这一列逐格原样」，
> 【11】那批 fixture（`10.0.0.1(管理IP范围)` 等）钉住取值层照常命中。

> 第 4 步的缺列**只告警不报错**：那五个时间列（尤其「事件遏制时间」「专家研判时间」是平台
> 近版才有的列）在客户环境里可能一行都不带，为它把整份报告打掉不划算。日志会明写
> 「这次没算时长、缺哪几列」——**缺列本身不静默，只是不致命中止**。
>
> 2026-10-10 起第 4 步多了一条**下游**：G7「威胁平均遏制时间」算的就是「事件遏制时间 −
> 专家研判时间」的均值（见 `CELL_REGISTRY.md` §8 G7）；同一天追加的第四列「响应时长」也是
> 一格的下游：G9「事件平均响应时长」（在同一批已处置事件里精确匹配「推送状态」=「已推送」
> 的行，取「响应时长」的非空均值 —— 没有样本时写 0，与 G7 写空串不是同一条口径，
> 见 `CELL_REGISTRY.md` §8 G9）。
> **2026-10-12 口径反转**：取值层改到预处理之后 —— 第 1、2、4 步（资产表建 IP 映射 +
> 事件表追加「内网外网资产」与四个时长列）**不再跑在报告落盘阶段**，改由
> `mssw_preprocess.js` 在**下载之后、解析之前**拉起，**原地改写事件表下载件**
> （`report_preprocess.py` 的 `preprocess_event_file`）。于是 G7 读到的就是这里追加出来的
> 「遏制时长」列本身、G9 读到的是同批的「响应时长」列 —— 同一个口径全仓只有
> `report_preprocess.py` 一处实现
> （从前那套"取值层现算 + 两份实现交叉钉住"已删除）。搬表本来就是直接从磁盘 xlsx 读的，
> 所以报告「事件表」sheet 上的那一列与取值层看到的**就是同一列**，不存在两处拼接。
> 上面那条「预处理缺列不报错」不变（第 4 步凑不齐源列时只记 `status`、不中止）；
> 变的是**取值层**：客户环境里这份导出缺那两个时间列时，G7 / G9 会**不写值 + 进错误列表**
> （不是数成 0），别的格子照常算。

> `--excel <p>` 复用现成 Excel 时**不走**这一步 —— 那份文件是调用方给的，本仓库不就地改它。

## 报告样式

合并完成后自动套用统一视觉规范：**除 `数据统计` 外的所有 sheet** 统一字体、表头色、底色、
边框、行高列宽与页面设置。

```text
--beautify-theme classic   # 默认：宋体 + 深蓝表头 #1F497D + 浅蓝底 #DCE6F2，左对齐
--beautify-theme modern    # 微软雅黑 + 蓝表头 + 隔行斑马纹，居中表头
--no-beautify              # 只合并，不套样式
```

规则定义在 `scripts/excel_beautifier/themes/`（`classic.json` / `modern.json` /
`shared_semantic.json`），改 JSON 即可调整，不用改代码。语义色按表头关键词命中：
「等级/级别」按严重度、「状态」按处置进展、「攻击结果」按攻击结果（该列「成功」是负面红色）。

美化失败不会导致报告丢失：数据已落盘，只在日志里报错并在返回值的 `beautify` 字段标记
`ok: false`，不会静默当成功。

## 取值现状：为什么成片大量印「失败」

**这是数据缺口，不是集成缺陷 —— 交付前必须知道，也如实告诉用户。**

以 `mss_classic_ops_2` + 现成 `一致性验收客户_report.xlsx` 实跑（真实 LLM `glm-5.1`，非 mock）：

| 项 | 实测 |
|---|---|
| 页数 / 占位符总数 | 40 页 / **198** 个（`source` 156、`group` 17、`chart` 10、`ai` 8、其他 7） |
| 有占位符的页 | 20 / 40；另外 20 页（目录、章节页、案例页、致谢、附录）**100% 模板原文** |
| `source` 位取不到值 | **116** 个 → 成片印**「失败」** |
| 取到模板原文而非业务数据（`手写` / `分布N`） | **29** 个 |
| 空值 | 24 个（`group` 槽位） |
| 成片里用户能直接看见的未替换 `{{token}}` | **9** 个，全在 P35/P36/P39/P40 |

成因：`excel_handler._put_text` 只在单元格有值时写 key，`_add_section` 只挂非空域，于是
**整个域从 raw 里消失**，它底下每个 descriptor `source` 路径就永远取不到。其中 48 个指向
5 个被整体丢弃的域（`security_assessment_notice_response_dashboard` 16、
`risk_operation_overview` 14、`threat_operation_overview` 12、
`offense_defense_exercise_defense_support` 3、`critical_assurance` 3）。

那 9 个可见 `{{token}}` 分两类：**8 个是 descriptor 已声明的图表位**
（`P27_bar` / `P28_pie_1` / `P30_combo` 这类），Excel 里没有对应图表数据 → 渲染整段 no-op，
模板占位符原样留下；**1 个 `security_value2` 在 `mss_classic_ops_2` 的 descriptor 里根本不存在**
（只出现在 simple / legacy 的 descriptor 里），任何数据都替换不了。

**判断「问题在数据还是在集成」最快的办法：换一份填满数据的 Excel，缺口就消失。**
同一套引擎、同一模板：

| | `一致性验收客户_report.xlsx`（本仓库产出） | `plus_data.xlsx`（数据齐） |
|---|---|---|
| `resolved_from_excel` | 40 | **154** |
| 印「失败」 | 116 | **2** |
| 模板原文 | 29 | **7** |
| 可见 `{{token}}` | 9 | **1** |

同样的 40 页、同样的 198 个占位符、同样的引擎代码 —— **唯一变量是 Excel**。

LLM 的表现值得注意：`glm-5.1` 有一部分产出是**如实承认数据缺口**
（“识别、响应、处置、闭环均为 0……无法量化”、“均为『手写』”），而不是编数字。
这是当前数据条件下**该有的**行为，**别当幻觉去修**。

按约定，本技能对 `失败` / `手写` 这类字面量**不做任何清洗**，如实暴露。

## 其他参数

- `--response-only`：保存原始 JSON 响应文件，而不是生成工作簿。
- `--beautify-theme` / `--no-beautify`：见上。
- `--type`：当前只支持 `asset | alarm | event | vuln | weakpwd`。
- ⚠️ `--protect-start` / `--protect-end`（重保/护网时间）**接受但无效**：
  `MIGRATION.md` R4 要求保留这两个参数，但它们**尚未接到任何取数逻辑上**，而 `args.js`
  对未知参数是**静默忽略**。传了不生效也不提示 —— **不要**向用户宣称重保时间已按这两个参数处理。
- `--xdr-cookie-path` / `--xdr-base-url` 已移除（无对应数据源）。
